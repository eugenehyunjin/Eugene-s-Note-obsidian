A Point 내용 정리:
- 사용 중인 Table
	1. new_coupons:
	- 쿠폰 발행 시, Detail 정보를 담고 있는 Table
	- point, total(쿠폰 수), type, status, 구분 등의 정보를 가지고 있음

	2. new_coupon_lists:
	- 실제로 사용하는 쿠폰 정보
	- 가장 중요한 쿠폰 code를 담고 있으며, 쿠폰 인쇄 or 쿠폰 발급 시, 가져오는 테이블
	- new_coupons의 idx 정보를 가지고 있음
	- use_flag & user_idx 입력하여 사용 처리
	- new_coupons와 1:M 관계

	3. new_coupon_use_lists:
	- 실제 이용 쿠폰 이용에 대한 로그 기록 용
	- new_coupon_lists와 1:2 관계(적립과 사용에 대한 기록)
	- 적립 시 couponList_idx(new_coupon_lists의 idx) 정보 필수 
	- 적립 시 해당 new_coupon_lists의 idx에 대해 사용 처리 동시 진행
	- 최종 레코드(reg_date 기준 최신)의 total_point에 적립된 총 포인트 표시
	
	4. apoints: 
	- 포인트를 사용할 때 insert, new_coupon_use_lists와 1:1로 매칭
	- 사용한 유저의 모든 정보를 담고 있음(pss_no,dancode, dong, ho), 동서 api 필수 정보 (엔드포인트 url: putAPoint/AP/yyyymm)
	- msg는 new_coupon의 name 컬럼 정보
	- get_point, use_point 정보를 가지고 있음
	- 웹에서 포인트 관리의 list 정보로 가져오는 Table

	5. pay_connects:
	- manager table에 가맹점 아이디 생성 후, 해당 계정과 매칭(manager_idx)
	- 포인트 가맹점의 발행한 쿠폰의 총 합계 정보 - amount
	- managers 생성 시, manager_groups에 STORE 그룹 정보로 추가해줌
	- 포인트 추가 시 (put_cash) amount에 + 처리 후, modify_date를 now로 업데이트
	
	6. pay_update_log:
	- pay_connects의 amount를 추가해줄 때 생성하는 로그 기록
	- 포인트 충전, 쿠폰 발급 2개의 타입으로 memo에 기록

	7. apoint_events
	- 등록하려고 하면 준비 중으로 처리 해 놓음
	- 이미지 등록 시, 해당 배너로 특정 단지에 팝업 생성
	- 이벤트 관련 페이지로 연결 처리 됨
	- 팝업 코드는 objects.php에 존재함
	- 정확한 이벤트의 활용 경로 파악이 어려움(지금은 단순 페이지 링크로 처리해 놓음)
	- 이벤트를 등록해도 쿠폰이 발급되지는 않고, 단순 이벤트 팝업을 특정 url로 연결해주는 용도

	8. apoint_event_files
	- apoint_events의 이미지 파일에 대한 정보를 담고 있는 table
	- 포인트 쿠폰과는 연결되어있지 않음

1. APOINT 관리 > 쿠폰 관리
- 발행 된 모든 쿠폰에 대해 확인 가능
- 쿠폰 발행 버튼을 통해 쿠폰 발행 가능
- 상점용 / 이벤트용 선택 가능
- 상점용: 최종 테스트는 상점용으로 테스트 진행
- 이벤트용: 쿠폰 중복 사용 여부, 지급 시점(이벤트 매너 클릭 시, 회원가입 시)등의 옵션 선택 가능
- 입력한 발행 매수대로 코드 생성(coupon_generator), new_coupon_lists 레코드 insert

- new_coupon_use_lists에 대한 리스트 내역 표시 및 관리
- 전체 쿠폰 사용 내역 확인 가능
- 상점용/이벤트용 구분하여 사용자 이름 검색 기능 제공

3. APOINT 관리 > 가맹점 관리
- 추가된 가맹점 내역 표시
- 가맹점 추가는 managers 테이블에 추가 되며, office_type 에 STORE로 관리자 계정 생성, 아이디/비밀번호 동일하게 처리
- managers 생성과 동시에 pay_connects 테이블에 레코드 생성하고, managers의 idx를 pay_connects의 manager_idx 컬럽에 값으로 추가 처리
- pay_connects의 amount 에서 해당 가맹점(관리자)가 발행한 쿠폰의 총 합계 금액을 표시해줌
- 위의 데이터를 토대로 가맹점 관리 페이지에서 충전포인트/발부포인트/남은포인트 내역을 명시해줌
- 슈퍼관리자가 가맹점 별로 포인트를 충전해주고, 해당 충전한 금액으로 가맹점은 가맹점 관리 페이지에서 쿠폰 발급이 가능함

4. APOINT 관리 > 이벤트 현황

  Future<ApiResponse<T>> getApi<T>({  
    required String path,  
    Map<String, dynamic>? queryParams,  
    required T Function(Object? json) fromJson,  
  }) async {  
    // 테스트 디버그 코드, 디버그 완료 후 아래의 주석된 코드로 대체  
    try {

      print("요청 성공: ${response.data}");  
      return ApiResponse<T>.fromJson(response.data, fromJson);  
    } catch (e, stackTrace) {  
      print("요청 실패: $e");  
      print("스택트레이스: $stackTrace");  
      rethrow;  
    }  
  
    // final response = await _dio.get(path, queryParameters: queryParams);  
    // return ApiResponse<T>.fromJson(response.data, fromJson);  }  
  
  Future<ApiResponse<T>> postApi<T>({  
    required String path,  
    Map<String, dynamic>? body,  
    required T Function(Object? json) fromJson,  
  }) async {  
    final response = await _dio.post(path, data: body);  
    return ApiResponse<T>.fromJson(response.data, fromJson);  
  }  
  
  Future<ApiResponse<T>> putApi<T>({  
    required String path,  
    Map<String, dynamic>? body,  
    required T Function(Object? json) fromJson,  
  }) async {  
    final response = await _dio.put(path, data: body);  
    return ApiResponse<T>.fromJson(response.data, fromJson);  
  }  
  
  Future<ApiResponse<T>> deleteApi<T>({  
    required String path,  
    Map<String, dynamic>? queryParams,  
    required T Function(Object? json) fromJson,  
  }) async {  
    final response = await _dio.delete(path, queryParameters: queryParams);  
    return ApiResponse<T>.fromJson(response.data, fromJson);  
  }  
}
